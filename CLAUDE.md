# Learning Hungarian

**Learning Hungarian** is an interactive educational website for learning the Hungarian language. Built with Jekyll and hosted on GitHub Pages.

- **Live Site**: https://jaypaulb.github.io/learninghungarian/
- **Tech Stack**: Jekyll (static site generator), Tailwind CSS (via CDN), Vanilla JavaScript
- **Theme**: Minima (Jekyll default)

## Quick Commands

```bash
# Local development (requires Jekyll installed)
bundle exec jekyll serve

# No build step needed - GitHub Pages builds automatically on push
```

## Code Conventions

### HTML Lesson Structure

All lesson files follow this pattern:

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Lesson N: Topic - Learning Hungarian</title>
    <link rel="icon" type="image/svg+xml" href="../favicon.svg">
    <script src="https://cdn.tailwindcss.com"></script>
    <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap" rel="stylesheet">
    <style>
        body { font-family: 'Inter', sans-serif; }
        /* Additional table/component styles */
    </style>
</head>
<body class="bg-slate-100 p-4 md:p-8">
    <header><!-- Back button + title --></header>
    <main class="max-w-3xl mx-auto bg-white rounded-xl shadow-md p-6">
        <!-- Content generated by JavaScript -->
    </main>
    <footer><!-- Copyright --></footer>
    <script>
        // Interactive lesson logic
    </script>
</body>
</html>
```

### Styling Guidelines

- **Framework**: Tailwind CSS via CDN (`https://cdn.tailwindcss.com`)
- **Font**: Inter (Google Fonts) - weights 400, 600, 700
- **Color Palette**: Slate/teal scheme
  - Background: `bg-slate-100`
  - Text: `text-slate-700`, `text-slate-600`
  - Accents: `#0f766e` (teal)
- **Responsive**: Mobile-first with `md:` breakpoint (768px)
- **Container**: `max-w-3xl mx-auto` for lesson content

### JavaScript Patterns

Lessons use vanilla JavaScript with this exercise pattern:

```javascript
// 1. Define question data
const questions = [
    { sentence: 'Én ___ tanár.', answer: 'vagyok', translation: 'I am a teacher.' },
    // ...
];

// 2. Build interactive UI
questions.forEach((q, idx) => {
    const input = document.createElement('input');
    input.className = 'border border-slate-300 rounded-md px-3 py-1 w-32 text-center';
    input.addEventListener('keydown', (e) => {
        if (e.key === 'Enter') checkAnswer(idx);
    });
    // ...
});

// 3. Validate answers
function checkAnswer(idx) {
    const isCorrect = input.value.trim().toLowerCase() === questions[idx].answer;
    feedback.textContent = isCorrect ? '✔️ Correct!' : '✖️ Try again!';
}
```

## Git Workflow

### Commit Convention

Use conventional commits format:

```
type(scope): message

# Examples:
feat(lessons): add final exercise section to "to be" lesson
fix(lesson): clarify Hungarian past tense word order
refactor(lessons): simplify lesson loading
docs(readme): update project structure
```

**Types**: `feat`, `fix`, `refactor`, `docs`, `style`, `test`, `chore`
**Scopes**: `lesson`, `lessons`, `alphabet`, `vowelsounds`, `layout`, `structure`, `index`

### Branch Naming

Feature branches should follow: `claude/description-sessionid`

## Adding New Content

### Creating a New Lesson

1. Create `lessons/new_lesson.html` following the HTML structure above
2. Add lesson link to `index.md`:
   ```markdown
   - [Lesson N: Topic](lessons/new_lesson.html)
   ```
3. Use Tailwind classes for styling
4. Keep JavaScript inline within the HTML file
5. Include a "Back to Lessons" navigation button

### Adding Images

- Place images in `/images/` organized by lesson topic
- Prefer SVG for scalability
- Reference with relative paths: `../images/alphabet/apple.svg`

## Important Guidelines

### Do's

- Use Tailwind utility classes for all styling
- Keep lessons self-contained (inline JS/CSS)
- Follow the existing question/answer exercise pattern
- Test interactive elements before committing
- Use semantic HTML and ARIA labels for accessibility
- Follow conventional commit format

### Don'ts

- Don't create external JS/CSS files (use inline)
- Don't add npm/bundler tooling without explicit request
- Don't break Jekyll build compatibility
- Don't add unsolicited documentation files
- Don't modify `_config.yml` without good reason

## Testing

No automated testing framework is configured. Manual testing checklist:

1. Verify lesson loads without JavaScript errors (browser console)
2. Test all interactive exercises (correct/incorrect answers)
3. Check responsive layout on mobile viewport
4. Verify navigation links work
5. Confirm Jekyll builds successfully (no Liquid errors)

## File Naming Conventions

- Lessons: `snake_case.html` (e.g., `verb_to_be.html`)
- Images: `lowercase.svg` or `lowercase.jpg`
- Markdown: `kebab-case.md` for documentation
